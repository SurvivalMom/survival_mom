# survival_mom アプリ／LP 制作スキル

## 1. 基本の作り方
- **HTML1ファイルで完結**（CSS・JSは同じファイル内）。GitHub Pages（`https://survivalmom.github.io/survival_mom/`）に置くだけで動く形にする
- 外部スクリプトは cdnjs.cloudflare.com から**バージョン固定**で読み込む（例：`react/18.3.1`）。`react@18` のような曖昧な指定はしない
- 保存は `localStorage`。読み書きは必ず `try/catch` で包み、使えない環境でも画面が壊れないようにする
- スマホ（幅390px前後）での見た目を最優先にする。母親はキッチンや寝かしつけの後に片手で開く
- フォントは既存と揃える：`Noto Sans JP` / `Zen Kaku Gothic New`（見出し）/ `Noto Serif JP`（しっとり系）
- ファイル名はローマ字の短い名前（例：`kokocheck.html`）。セットで作るもの：
  - 本体 `xxx.html`
  - 体験版 `xxx_taiken.html`（あれば）
  - LP `lp_xxx.html`
  - 購入後ページ `success_xxx.html`

## 2. パスワード（いちばん大事・必ず守る）
**平文のパスワードをソースに書かない。** GitHub Pagesは「ソースを表示」で誰でも中身を読めるため。

### A. 買い切りアプリ（簡易ゲート）
1. このフォルダの `smhash.js` の中身を `<head>` 直後に `<script>` で貼る
2. パスワードのSHA-256を計算して、その値だけを書く：
   ```bash
   python3 -c "import hashlib,sys;print(hashlib.sha256(sys.argv[1].encode()).hexdigest())" 'パスワード'
   ```
3. 照合は `smHash(入力値) === 'ハッシュ値'` の形にする
4. 書いてはいけない例：`const correctPassword = 'kokoro'`、`simpleHash('map')`（関数に平文を渡す形もNG）

これはあくまで「覗き見防止」です。開発者ツールを使えばすり抜けられ、短い単語は総当たりで当てられます。パスワードは **8文字以上・英数字混在** を推奨します。

### B. 月額・施設向け・高単価アプリ（本当に守りたいもの）
既存のCloudflare Worker方式を使う（`cocolog_v2.html` / `ikuseilog.html` / `kizuki.html` / `kirokuwake.html` が実例）：
- `WORKER_URL = 'https://cocolog-license.sr-g-solti.workers.dev'` に `{ code, deviceId, app }` をPOSTし、`data.ok` で解錠する
- コード発行の手順は `kirokuwake_SETUP.md` を参照する

### C. パスワード一覧を中に表示するページ（例：`omatome.html`）
- ゲートを付けても、一覧の文字列はソースに残る。「ゲートをハッシュにしたから安全」と説明しない
- 守りたい場合は B方式にするか、一覧そのものを暗号化する

### 作った後の確認
- `grep -rn "実際のパスワード" *.html` を実行し、何も出てこないこと（平文が残っていないこと）を確認する
- ブラウザで「正しいパスワードで開く」「間違いでは開かない」の両方を確かめる

## 3. 購入導線
- 購入ボタンは Stripe Payment Link（`https://buy.stripe.com/...`）。既存LPと同じボタンの見た目に揃える
- `success_xxx.html` には、アプリのURL・起動パスワード（またはコード）・「このページをブックマークしてください」を載せる
- **購入後ページのURLは推測されやすいので、実際の購入者だけが知る情報に頼りすぎない**（高単価ならB方式にする）

## 4. LPのコピー基準
ターゲットは「不登校・発達グレー・中学受験を抱える30代の母親」。書いたら、次の3軸で自己採点する（①40点・②30点・③30点、合計100点）。**95点未満なら、減点理由を3つ挙げて書き直す。**

1. **「今」の解像度**：朝の玄関、宿題の時間、学校からの電話、深夜の検索、SNSでの比較など。生活の生々しい一場面から入っているか
2. **欲しい未来**：機能の説明ではなく「このアプリを使った後の、ある日の情景」を2つ以上描けているか。何から解放されるかを言葉にしているか
3. **動きたくなる伝え方**：正論や専門家目線になっていないか。「わかる…」「これならできそう」と思える小さな一歩（3分でできる、など）を示しているか

ファーストビューに必ず入れるもの：
- 「〇〇なあなたへ」というターゲティングコール
- 悩みへの共感
- 「あなただけじゃない」という一文

避けること：
- 「綺麗事ばかりで現実と違う」と思われる表現
- 上から目線
- 「できない自分」を責めるように読める言い回し
