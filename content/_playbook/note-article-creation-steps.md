# 売れるnote記事の作成手順（note記事特化版）

weekly-production-prompt.md のSTEP Bを、note記事単体の制作フローとして
独立させ、判断基準を具体化したもの。画像・動画（STEP C/D）を作らない
単発のnote執筆でも、この手順だけで再現できることを目的とする。

各STEPの末尾に「✅ 次に進む前のチェック」を置く。すべてにチェックが
入るまで次のSTEPに進まない。さらに、各STEPの成果物（テーマ、タイトル案、
リサーチ要約、章立て、有料/無料部分の本文、品質採点、付随素材、公開後
導線）はその都度ユーザーに提示し、「これで良いか」の承認を得てから
次のSTEPに進む。自己判断だけで先に進めない。

---

## STEP 0：起動前に揃えるもの
- 既存note記事一覧（タイトル・公開日・価格・切り口） — 重複回避チェック用
- 想定公開日（曜日・季節性の有無）
- 今の時期に刺さる季節/時事フック（夏休み・新学期・進級・長期休暇明けなど）
- 読者が実際に検索しそうな自然文キーワード候補2〜3個
  （例：「不登校 初期対応」「発達障害グレーゾーン 小学生」）

✅ 次に進む前のチェック
- [ ] 既存note記事一覧を確認した
- [ ] 想定公開日を決めた
- [ ] 季節/時事フック候補を1つ以上挙げた
- [ ] 検索キーワード候補を2〜3個挙げた
- [ ] ユーザーに提示し、この内容で良いか承認を得た

---

## STEP 1：テーマ選定（切り口を1つに絞る）
1. 既存note記事一覧と照合し、テーマ・切り口の重複がないか確認する
   （きょうだい児/えこひいき/学校電話/夫婦/受験など既出領域は避け、
   未開拓の感情領域を探す）
2. 「今の季節・時事性」×「ターゲット読者が“今まさにイライラしていること”」
   を掛け合わせ、フックを1つに絞る
3. フックに対応する検索キーワードを2〜3個特定する
   （SNS検索・発見タブ経由の新規流入を狙うため。以降のタイトル・本文に
   自然文で織り込む前提を作る）

✅ 次に進む前のチェック
- [ ] 既存記事と切り口が重複していないことを確認した
- [ ] フックを1つに絞った
- [ ] フックに対応する検索キーワードを2〜3個確定した
- [ ] ユーザーに提示し、この内容で良いか承認を得た

## STEP 2：タイトル決定
- タイトル案を5つ作る（35文字前後）
- 以下の条件のうち**3つ以上**を満たすこと（説明型タイトルは禁止）
  1. 痛み（読者が今抱えている具体的な苦しさ）
  2. 欲しい未来（読者が本当に望んでいる状態）
  3. 具体性（時刻・金額・セリフなど生活のディテール）
  4. survival_momらしい独自視点（一般論ではない一次情報の角度）
- 5案の中から最も刺さるものを1つ選定してから次に進む

✅ 次に進む前のチェック
- [ ] タイトル案を5つ作った
- [ ] 各案が4条件のうち3つ以上を満たしている
- [ ] 説明型タイトルが混じっていない
- [ ] 採用するタイトルを1つ選定した
- [ ] ユーザーに提示し、この内容で良いか承認を得た

## STEP 3：リサーチ
- WebSearchで一次情報を収集する（AI生成のみでの断定は禁止）
- リサーチ内容を先に要約・報告し、確認を得てから構成設計に入る
- 医療・制度に関わる話題（起立性調節障害、発達特性など）は出典URLを
  必ず残す

✅ 次に進む前のチェック
- [ ] WebSearchで一次情報を収集した
- [ ] リサーチ内容を要約し、確認を得た
- [ ] 医療・制度関連の話題は出典URLを残した
- [ ] ユーザーに提示し、この内容で良いか承認を得た

## STEP 4：構成設計〜執筆（章立て→有料部分→無料部分の順で作る）
構成と執筆は一気に無料部分から書き下さず、以下の順で進める。
先に「確実に伝えたい中身」を固めてから、それを一番魅力的に見せる
入り口（無料部分）を設計するという流れにする。

### 4-1：全体の章立てを考える
- 無料/有料を通しで、記事全体の章（見出し）を先に箇条書きで洗い出す
- この時点では文章化しない。章の並び＝読者が体験する順番として、
  「問題提起→共感→（ここから有料）→解決の道具→再現性→締め」のような
  流れになっているかを確認する
- 章立てが破綻していないか（重複する章、抜けている段階がないか）を
  ここで確定させてから次に進む

✅ 4-1のチェック（4-2に進む前）
- [ ] 無料/有料通しの章立てを箇条書きで洗い出した
- [ ] 章の並びが読者の体験順になっている
- [ ] 重複・抜けがないことを確認した
- [ ] ユーザーに提示し、この章立てで良いか承認を得た

### 4-2：有料部分を先に書く（確実に伝えたい内容）
- 有料部分の各章から、説明文ではなく「使える道具」として書く
  - 書き込み式ワークシート
  - 交渉/会話セリフ集
  - 1週間プラン雛形
  - ケーススタディ
  - Q&A
- 有料部分で紹介するツールを「プロフィールから受け取れます」と案内する
  場合、記事内で完結させず、実際に受け取れる別成果物（Webアプリ等）と
  して必ず用意する。記事本文に全文書いてあるものを「受け取れます」と
  案内しない
- ケーススタディの扱いは下記「注意」を参照

✅ 4-2のチェック（4-3に進む前）
- [ ] 有料部分が説明文ではなく「使える道具」として書けている
- [ ] 「受け取れます」と案内するものは、記事外の別成果物として実在する
- [ ] ケーススタディを使う場合、下記の注意事項に沿っている
- [ ] ユーザーに提示し、有料部分の内容で良いか承認を得た

### 4-3：有料部分の構成が固まってから無料部分を書く
- 有料部分で何を渡すかが先に確定しているので、無料部分は
  「それを読みたくなる入り口」として逆算して書ける
- 無料部分は問題提起と共感まで。核心の解決策は一歩手前でぼかし、
  答えを出し切らない
- 無料部分の最後は、有料部分で渡す具体的な中身（4-2）へ
  自然につながる一文で締める

✅ 4-3のチェック（本文チェックリストへ進む前）
- [ ] 無料部分が有料部分の内容から逆算して書けている
- [ ] 核心の解決策を出し切らず、一歩手前でぼかしている
- [ ] 無料部分の締めが有料部分へ自然につながっている
- [ ] ユーザーに提示し、無料部分の内容で良いか承認を得た

本文全体（無料＋有料）には以下を**すべて**入れる。
- [ ] 冒頭に読者への直接的な問いかけ（タイトルの一言を反復するフック）
- [ ] 失敗/後悔した一言（「言ってはいけなかった一言」）
- [ ] 生活の生々しいディテール（金銭的負担・深夜の検索行動・SNSでの
      比較疲れなど）
- [ ] 欲しい未来の具体的な情景を2つ以上（抽象語で終わらせない）
- [ ] 有料部分への遷移に「それ、私にもできそう」と思わせる一文
- [ ] STEP 1で決めた検索キーワードのうち最低1つを、タイトルまたは
      冒頭300字以内に不自然にならない形で含める

### ケーススタディの扱い（注意）
本文が一人称の告白調で通っている場合、有料部分に説明なく「Aさん」
「Bさん」のような第三者のケーススタディを挿入すると、取ってつけた
一般論に見えて不自然になる。以下のいずれかで対応する。
- 記事内に時間軸の対比（去年/今年など）があるなら、それを使って
  「去年の私と、今年の私」という一人称の比較に置き換える（推奨）
- 第三者の話がどうしても必要な場合は、「同じ相談窓口で知り合った」
  「コメント欄で聞いた」など、語り手がその人を知っている経緯を
  一文添えて地続きの声に見せる

✅ STEP 4 全体のチェック（STEP 5に進む前）
- [ ] 上記「本文全体」の6項目をすべて満たしている
- [ ] 本文全体（無料＋有料）をユーザーに提示し、良いか承認を得た

## STEP 5：品質チェック（95点未満は公開しない）
以下3軸・配点100点で自己採点する。
| 軸 | 内容 | 配点 |
|---|---|---|
| ①今の解像度 | 読者の「今」がどれだけ生々しく描けているか | 40 |
| ②欲しい未来の言語化 | 抽象語で終わらせず、情景として描けているか | 30 |
| ③動きたくなる伝え方 | 読者が有料部分を開きたくなる流れになっているか | 30 |

95点未満の場合、減点理由を3つ挙げてリライトする。95点以上になるまで
繰り返し、到達したら確定する。

✅ 次に進む前のチェック
- [ ] 3軸で自己採点した
- [ ] 合計95点以上である（未満なら減点理由を3つ挙げてリライトを繰り返した）
- [ ] 採点結果をユーザーに提示し、確定して良いか承認を得た

## STEP 6：付随素材の出力
1. アイキャッチ画像プロンプト（英語）
2. ハッシュタグ（3〜5個、汎用感情タグより検索されやすい具体名詞句を優先）
3. note投稿用コードブロック（本文をそのまま貼れる形式）

✅ 次に進む前のチェック
- [ ] アイキャッチ画像プロンプトを出力した
- [ ] ハッシュタグを3〜5個に厳選した
- [ ] note投稿用コードブロックを出力した
- [ ] ユーザーに提示し、この内容で良いか承認を得た

## STEP 7：公開後の導線
- 記事末尾に、コメントでの読者との対話を促す一文を入れる
  （例：「今のあなたの家の様子をコメントで教えてもらえたら嬉しいです」）
- フォローで次の記事が届くことを明記する
- 有料ツールのCTAは記事内で単一のリードマグネットに統一し、
  他のSNS投稿（画像・動画）を作る場合も同じ導線に揃える

✅ 公開前の最終チェック
- [ ] コメント誘導の一文を入れた
- [ ] フォロー導線を明記した
- [ ] CTAが単一のリードマグネットに統一されている
- [ ] ユーザーに提示し、公開して良いか最終承認を得た

---

## 共通ルール（毎回固定）
- 「ヒント」「参考になる」等の曖昧なCTA表現、アスタリスク強調、
  感情パートの箇条書き、機械的な列挙は禁止
- Unique（独自視点）／Specific（〇〇の場合等の具体事例）／Authentic
  （現場経験に基づく一次情報）の3条件を満たすこと
- 既存note記事との重複はSTEP 1で毎回機械的にチェックする
- ターゲット読者の家庭構成を出生順や性別で決め打ちしない
  （役割ベースで表現する）
