# リールを仕上げたあとの冒頭チェック（両アカウント共通）

リール動画を仕上げたら、投稿する前に「冒頭6秒チェッカー」（`hook_yosoku.html`、公開ページ https://survivalmom.github.io/survival_mom/hook_yosoku.html ）と同じ分析をかけ、伸びた例と比べて足りない要素を確かめてから渡す。

2026-11-27 に、点数を当てる道具（6秒残存の予測）から、要素に分けて分析する道具に書き換えた。
2万ビューを超えた「特変なしが一番危ない」も、ふだんの100ビュー台のリールも、予測はどちらも55〜58%で見分けられなかったため。新しい分析では、前者が 8/8、後者が 4/8 と差が出た。

## 手順
1. 動画を仕上げる（care_design_lab は `content/caredesign/_playbook/lt_reel.py`。火曜の声つき・言い切り型は Gemini で生成）
2. 分析をかける
   ```
   python3 content/_playbook/hook_check.py 完成.mp4 --brand sm|cdl --theme "伝えたいこと" --audio "人の声（ナレーション・セリフ）あり・BGMなし" --spoken "ナレーションの言葉" --out 結果.json
   ```
   - `--brand`：survival_mom_diary は `sm`、care_design_lab は `cdl`
   - `--audio`：音は送らないので言葉で伝える（「人の声（ナレーション・セリフ）あり・BGMなし」「人の声とBGMの両方」「BGMだけ」「環境音だけ」「音なし」）
   - アプリの「🎬動画」と同じく、0〜6秒の13枚の静止画だけを送る（動画そのもの・音声は送らない）
   - 分析の文言・ペルソナ・伸びた例は、毎回 `hook_yosoku.html` から読み込む。アプリを直せば、自動チェックにもそのまま反映される
3. 見るところ
   - **伸びた例と同じ要素（x/8）**：8つの要素（常識をひっくり返す一言／人の顔・表情／人の声／2〜3秒ごとに画が変わる／字幕が短い／具体的な場面／ターゲット本人の目線／6秒までに先が気になる）のうち、いくつあるか
   - **2秒の関門**（指が止まるか）と**6秒の関門**（続きを見る理由があるか）が「通る・あやうい・通らない」のどれか
   - **秒ごとの分解**（区間ごとの見出しつき）で「離れる人：大」の瞬間
   - **直すとよいところ**の「撮り直し不要」のもの
4. 直す：「撮り直し不要」の直し（冒頭の言葉・字幕の長さと位置・カット割り・6秒までの予告）を入れて、もう一度分析する。やり直しは2回まで。言葉を足して長くする直しはしない。「撮り直しが必要」なものは、直さずにユーザーに伝える
5. 記録する：スプレッドシート（ID: 1noRJWcQR7muqEXVCORtfo4RjOk4Czaa_QBz3ytT0Xpg）の「冒頭チェック」タブに、投稿日・アカウント・タイトル・何回目・伸びた例と同じ要素（x/8）・見立て・離れる人が多い瞬間・直したこと、を1回ごとに1行で書く（F列は x/8 で書く。2026-11-27 までの行は6秒残存の予測%）
6. ユーザーに渡すときは、x/8、2秒・6秒の関門の結果、足りない要素、直したことを一言添える

## 投稿後
- アプリの結果画面の「投稿後の数字を記録する」に、ビュー・3秒視聴率・平均視聴時間・保存・シェアを入れる。「これまでの分析」に、要素ごとの平均ビューと、「要素の数と実際の数字は合っているか」の表がたまる（10本ほどで目安になる）。HookAce などの予測ツールが実際の視聴データで合わせ込んでいるのと同じことを、自分のアカウントの数字でやるため
- 大きく伸びた投稿が出たら、`hook_yosoku.html` の `BRANDS` の `winners`（伸びた例）に書き足す。分析の手本が増える

## 気をつけること
- x/8 は「伸びた例との似かた」の目安で、何%残るかの予測ではない。型が違う回（木・土のテロップ型など）は「人の声」「人の顔」がなくても構わない。その回の型で直せるところを直す
- 窓口（`workers/ai-proxy.js`）は、公開ページ以外からの呼び出しを合言葉ヘッダー `x-sm-key` で受け付ける。設定は `workers/README.md` の「ステップ5」
- 分析のたびに窓口の Gemini の利用量を使う。1本あたり最大3回（最初＋やり直し2回）まで
